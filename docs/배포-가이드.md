# 배포 가이드 — Supabase + Vercel

여행 데이터를 외부(집 밖·다른 기기)에서도 쓰도록 **Supabase(DB·로그인)** 와 **Vercel(사용자 웹 · 운영 콘솔)** 로 옮기는 방법입니다.

```
 모바일 앱 (Expo)           ─┐
 사용자 웹 (Vercel, web/)    ─┼─►  Supabase  (Postgres + 이메일 로그인 + 접근 규칙 RLS)
 운영 콘솔 (Vercel, admin/)  ─┘
```

## 0. 화면 구성 — 사용자용과 운영자용을 분리했습니다

| 구분 | 폴더 | 로컬 주소 | 대상 | 하는 일 |
|------|------|-----------|------|---------|
| **사용자 웹** | `web/` | <http://localhost:5173> | 일반 사용자 (회원가입 가능) | 내 여행·일정·장소·바우처·회화·준비물 준비 |
| **운영 콘솔** | `admin/` | <http://localhost:5174> | **운영자만** (가입 없음) | 가입자·접속 대시보드, 사용자 관리, 접속 로그 |
| **모바일 앱** | `mobile/` | — | 일반 사용자 | 여행 중 보기·메모·사진·지도 |

- 운영 콘솔은 **관리자로 등록된 계정만 로그인**됩니다. 일반 계정으로 로그인하면 바로 거부되고, 사용자 웹과는 주소·로그인·화면 색(어두운 사이드바 + 노란 상단선)이 완전히 다릅니다.
- 사용자 웹에는 운영 메뉴가 없습니다. 두 웹은 **서로 다른 Vercel 프로젝트(다른 주소)** 로 배포합니다.

- 별도 API 서버가 없습니다. 앱과 두 웹이 Supabase를 직접 호출하고, **본인 계정으로 로그인한 경우에만** 데이터를 읽고 쓸 수 있습니다.
- 사진 원본은 지금처럼 **기기에만** 있고, 서버에는 촬영 시각·위치 같은 메타데이터만 저장됩니다.
- 기존 `backend/`(Spring Boot + H2)는 더 이상 필요하지 않습니다. 이전이 끝나면 보관하거나 삭제하세요.

## 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 로그인 → **New project**
2. 이름 `honeymoon-guide`, 리전은 **Northeast Asia (Seoul)** 권장, DB 비밀번호는 안전한 곳에 보관
3. 생성이 끝나면 왼쪽 **SQL Editor** → New query
4. `supabase/migrations/0001_init.sql` 내용을 붙여넣고 **Run**
   - 테이블 9개, 일차 자동 생성 트리거, 일정 교체 함수, 접근 규칙(RLS)이 한 번에 만들어집니다.
   - 오류 없이 `Success` 가 나오면 됩니다.

## 2. 로그인·회원가입 설정

앱과 사용자 웹 로그인 화면에 **로그인 / 회원가입** 탭이 있습니다. (운영 콘솔에는 가입이 없습니다.) 가입하려면 Supabase 설정이 아래처럼 되어 있어야 합니다.

1. **Authentication → Sign In / Providers → Email**: 사용 켜기
2. 같은 화면에서 **Allow new users to sign up** 을 **켜기** (꺼져 있으면 앱에 "현재 가입이 막혀 있어요"라고 나옵니다)
3. **Confirm email** (가입 확인 메일) 선택
   - **켜면**: 가입 후 메일의 링크를 눌러야 로그인할 수 있습니다. 링크는 **Site URL** 로 열리므로 Authentication → URL Configuration 의 Site URL 을 실제 주소(Vercel 주소)로 맞춰야 합니다. 기본 제공 메일은 시간당 발송 수 제한이 작습니다.
   - **끄면**: 가입과 동시에 로그인됩니다. 개인용·부부용이라면 이쪽이 편합니다.
4. (권장) **Minimum password length** 를 8자 이상으로

> 데이터는 **계정별로 분리**됩니다. 누가 가입해도 다른 사람의 여행은 보이지 않습니다(RLS).
> 부부가 같은 여행을 함께 보려면 지금은 **하나의 계정을 같이 쓰세요.** (계정 간 공유는 추후 확장 사항)

> 가입을 **막고 싶다면** 2번을 끄고, Authentication → Users → Add user 로 본인 계정만 직접 만드세요.

## 2-1. 운영자(관리자) 기능 켜기

가입자·접속 현황 대시보드, 사용자 관리(정지·권한·삭제), 접속 로그를 보려면 두 번째 SQL을 실행하고 첫 관리자를 지정해야 합니다.

1. SQL Editor 에서 아래 두 파일을 **순서대로** 붙여넣고 각각 **Run**
   - `supabase/migrations/0002_admin.sql` (관리자 목록 · 접속 로그 · 대시보드/사용자/로그 함수)
   - `supabase/migrations/0003_admin_users.sql` (사용자 상세 · 이메일/이름/메모 수정 · 기간·사유 정지)
   - `supabase/migrations/0004_catalog_insights.sql` (관광지 카탈로그 · 운영 기록 · 인사이트 · 휴면 필터)
   - `supabase/migrations/0005_password_ip.sql` (비밀번호 변경·초기화 · 사용자 IP/기기 정보 · 비밀번호 변경 요구)
2. **본인 계정을 먼저 가입**한 뒤, SQL Editor 에서 아래를 본인 이메일로 한 번 실행해 첫 관리자로 지정

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'me@example.com'
on conflict do nothing;
```

3. **운영 콘솔**(<http://localhost:5174>)에서 로그인하세요. 관리자로 등록된 계정만 들어갈 수 있고, 일반 계정은 "관리자 권한이 없는 계정입니다"로 거부됩니다.
   (운영 콘솔 로그인 화면에서 오류가 보이면 그 문구가 원인입니다 — 예: `0002`/`0003` SQL 미적용)
   이후 다른 관리자는 사용자 관리 화면에서 **관리자 지정** 으로 추가할 수 있습니다.

**관리자가 할 수 있는 것**

| 화면 | 내용 |
|------|------|
| 운영 대시보드 | 전체·신규 가입자, 오늘/7일/30일 접속자, 정지·미인증 계정 수, 일별 가입·접속 그래프 (한국 시간 기준) |
| 사용자 관리 | **계정 추가**, 이메일·이름·**IP** 검색, 상태 필터(**비밀번호 변경 필요** 포함), 목록에 최근 IP 표시. 행을 누르면 **상세 패널**: 표시 이름·이메일·운영자 메모 수정, 이메일 인증 처리, **기간·사유를 지정한 정지**/해제(로그인 중인 기기도 즉시 로그아웃), 관리자 지정/해제, 비밀번호 재설정 메일, 계정 삭제, 해당 사용자의 최근 접속 기록 |
| 접속 로그 | 가입·로그인·앱 실행·로그아웃 기록, 기기(Android/iOS/웹)·이벤트·이메일 필터, **CSV 내보내기** |
| 인사이트 | 사용 단계별 전환율(가입→여행→일정→…), 시간대·요일별 접속, 기기별 비율, 인기 여행 국가·목적지 Top 10, 콘텐츠 총량, 휴면 사용자 수 |
| 운영 기록 | 운영자가 한 작업(정지·해제·수정·삭제·권한·관광지 변경)이 자동 기록됨. 삭제·수정할 수 없는 감사 기록 |
| 관광지 관리 | 나라별 관광지·좌표 등록/수정/숨김/삭제, **CSV 일괄 등록**·내보내기 (아래 2-2) |

**지켜지는 안전 장치**

- 관리자 여부는 DB 의 `admins` 테이블로만 판정합니다. 주소를 직접 쳐서 들어가도 DB 함수가 거부합니다.
- 관리자도 **다른 사용자의 여행·메모·티켓 내용은 볼 수 없습니다.** (여행 "개수" 같은 집계만 확인)
- 이메일을 바꾸면 사용자는 새 이메일로 로그인해야 합니다. 비밀번호를 운영자가 직접 바꾸는 기능은 일부러 두지 않았고, **재설정 메일**로만 바꿉니다.
- 표시 이름·메모·정지 사유는 운영자만 볼 수 있고 사용자 본인에게는 보이지 않습니다.
- 자기 자신은 정지·삭제·권한 해제를 할 수 없고, 관리자 계정은 먼저 권한을 해제해야 정지·삭제할 수 있습니다.
- `service_role` 키는 쓰지 않습니다. 모든 기능이 SQL 함수(SECURITY DEFINER)와 RLS 로 동작합니다.

**접속 로그와 개인정보**

- 앱·사용자 웹·운영 콘솔이 로그인·앱 실행 때마다 기록을 남깁니다. 접속 IP 는 Supabase 가 전달하는 요청 헤더에서 읽으며 환경에 따라 비어 있을 수 있습니다.
- IP 는 개인정보로 볼 수 있으므로, 가입자에게 수집 사실을 안내하고 보관 기간을 정해 주기적으로 지우세요.

```sql
delete from public.access_logs where created_at < now() - interval '90 days';
```

- 정지한 계정은 이후 로그인할 수 없으며, 이미 로그인된 기기는 짧은 시간 안에 로그아웃됩니다.

## 2-1-1. 계정 추가 · 비밀번호 관리 · IP 정보

**계정 추가** (운영 콘솔 → 사용자 관리 → 계정 추가)

1. 이메일을 넣으면 **임시 비밀번호가 자동 생성**됩니다. (다시 생성·직접 입력도 가능, 8자 이상 · 영문자+숫자 포함)
2. 옵션: 이메일 인증 완료 처리(바로 로그인), **첫 로그인 때 비밀번호 변경 요구(권장)**, 관리자 권한 부여, 표시 이름·메모
3. "계정 만들기" 직후 이메일/임시 비밀번호가 한 번만 표시됩니다. 복사해서 사용자에게 안전한 방법으로 전달하세요. (창을 닫으면 다시 볼 수 없음)

> 계정 추가는 Supabase 의 가입 기능을 사용하므로 **새 사용자 가입 허용**이 켜져 있어야 합니다. 운영자 로그인은 그대로 유지됩니다.

**비밀번호 변경 · 초기화** (사용자 상세 → 비밀번호 관리)

| 기능 | 동작 |
|------|------|
| 임시 비밀번호로 초기화 | 무작위 임시 비밀번호 적용 + 로그인 중인 기기 모두 로그아웃 + 다음 로그인 때 변경 요구 |
| 비밀번호 직접 지정 | 운영자가 정한 값 적용(정책 검사), 변경 요구는 선택 |
| 변경 요구 켜기/끄기 | 켜면 사용자는 **로그인 직후 새 비밀번호를 정해야** 앱·웹을 쓸 수 있음 |
| 재설정 메일 | 사용자가 직접 새 비밀번호를 정하도록 메일 발송 |
| 내 비밀번호 변경 | 운영 콘솔 상단 "비밀번호 변경" (운영자 본인) |

- **비밀번호 정책**: 8~72자, 영문자와 숫자 각 1개 이상, 이메일과 같지 않을 것. (DB 함수와 화면이 같은 규칙)
- 비밀번호는 **bcrypt 해시로만 저장**되고, 운영 기록에는 "누가 · 누구에게 · 변경 요구 여부"만 남으며 **비밀번호 값은 어디에도 기록되지 않습니다.**
- 사용자는 앱(설정 → 계정 → 비밀번호 변경)과 사용자 웹(상단 "비밀번호 변경")에서도 스스로 바꿀 수 있습니다.
- 임시 비밀번호를 받은 사용자는 앱·웹 로그인 직후 **새 비밀번호 설정 화면**이 먼저 나옵니다. ("나중에 하기"는 로그아웃)

**IP · 기기 정보** (사용자 상세 → 접속 정보)

- 최근/최초 IP, 최근 기기, 가입 방식, 기기별 접속 횟수, **IP별 접속 횟수와 처음·마지막 시각**을 볼 수 있습니다.
- 사용자 목록에 "최근 IP" 열이 있고, 검색창에 **IP 주소를 그대로 입력**하면 그 IP로 접속한 계정을 찾을 수 있습니다. (정확히 일치)
- IP 는 Supabase 가 전달하는 요청 헤더에서 읽으므로 환경에 따라 비어 있을 수 있습니다. 개인정보로 볼 수 있으니 보관 기간을 정해 주기적으로 정리하세요.

## 2-2. 추천 관광지(카탈로그) — 나라별 좌표를 미리 등록해 두기

운영자가 관광지와 좌표를 등록해 두면, 사용자는 일정에 장소를 넣을 때 **직접 좌표를 찾지 않고 검색해서** 담을 수 있습니다.

**운영자 (운영 콘솔 → 관광지 관리)**

1. **관광지 등록**: 나라, 도시, 이름, 현지·영문 이름, 분류, **좌표**, 주소, 설명을 입력합니다.
   - 좌표는 구글 지도에서 장소를 우클릭하면 나오는 `41.4036, 2.1744` 를 그대로 붙여넣으면 됩니다. "구글 지도에서 확인" 링크로 위치를 바로 검증할 수 있어요.
2. 많이 등록할 때는 **CSV 일괄 등록**: "양식 받기" → 엑셀에서 채우기 → 저장(CSV) → 파일 선택. 오류가 있는 줄은 미리보기에서 이유와 함께 표시되고, 이미 등록된 항목(나라·도시·이름 동일)은 건너뜁니다.
3. "공개"를 끄면 사용자에게 숨겨지고(삭제하지 않고 잠시 내릴 때), 삭제해도 사용자가 이미 가져간 장소는 그대로 남습니다.

**사용자**

- **앱**: 일정 편집 → 장소 추가 → **추천 관광지** 탭. 이 여행의 나라가 등록돼 있으면 자동으로 그 나라가 선택돼요. 항목을 누르면 내 장소에 담기고 일정에 바로 추가됩니다.
- **사용자 웹**: 장소 관리, 여행 계획 → 일차 구성의 "추천 관광지에서 찾기".
- 같은 관광지를 다시 담아도 내 장소가 중복되지 않습니다.

> 카탈로그는 모든 로그인 사용자가 **읽기만** 할 수 있고, 등록·수정·삭제는 관리자만 가능합니다(DB 규칙으로 강제).

## 3. 키 확인

**Project Settings → API** 에서 두 값을 복사합니다.

| 항목 | 용도 |
|------|------|
| **Project URL** (`https://xxxx.supabase.co`) | 앱·웹 공통 |
| **anon public** 키 | 앱·웹 공통 (공개되어도 되는 키) |

> ⚠️ **`service_role` 키는 절대 앱·웹·저장소에 넣지 마세요.** 모든 보호 규칙을 우회하는 관리자 키입니다.
> anon 키만 사용하면, 키가 노출돼도 RLS 때문에 로그인 없이는 아무것도 읽을 수 없습니다.

## 4. 로컬 실행 설정

**모바일 앱** — 루트 `.env` 에 추가 (이미 `google_maps_api_key` 가 있는 파일)

```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_ANON_KEY=eyJ...anon-key...
```

**사용자 웹** — `web/.env` 파일을 만들고 (`web/.env.example` 참고)

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...anon-key...
VITE_GOOGLE_MAPS_API_KEY=          # 지도 선택 기능용 (선택)
```

**운영 콘솔** — `admin/.env` 파일을 만들고 (`admin/.env.example` 참고). Supabase 두 값만 있으면 됩니다.

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...anon-key...
```

설정 후 각각 다시 시작합니다. (같은 Supabase 값을 두 파일에 넣으면 됩니다.)

```powershell
cd web
npm install
npm run dev          # http://localhost:5173 → 사용자 웹

cd ..\admin
npm install
npm run dev          # http://localhost:5174 → 운영 콘솔

cd ..\mobile
npm install
npx expo start --web --port 8081   # 앱 → 로그인 화면
```

`.env` 류는 `.gitignore` 에 포함되어 있어 커밋되지 않습니다.

## 5. Vercel 배포 (사용자 웹 + 운영 콘솔 — 프로젝트 2개)

같은 저장소로 **Vercel 프로젝트를 두 개** 만듭니다. (주소가 달라야 사용자와 운영자 화면이 섞이지 않습니다.)

1. 저장소를 GitHub에 올립니다. (`.env` 류는 올라가지 않는지 확인)
2. <https://vercel.com> → **Add New → Project** → 저장소 선택 (두 번 반복)

| 프로젝트 | Root Directory | Environment Variables | 예시 주소 |
|----------|----------------|-----------------------|-----------|
| 사용자 웹 | `web` | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_GOOGLE_MAPS_API_KEY` | `honeymoon-guide.vercel.app` |
| 운영 콘솔 | `admin` | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | `honeymoon-admin.vercel.app` |

- Framework 는 Vite 로 자동 인식되고, 각 폴더의 `vercel.json` 이 SPA 라우팅을 처리합니다.
3. 각각 **Deploy** 한 뒤, Supabase **Authentication → URL Configuration** 의 **Site URL** 을 **사용자 웹 주소**로 바꿉니다. (가입 확인 메일의 링크가 사용자 웹으로 열립니다.)
4. (권장) 운영 콘솔 주소는 사용자에게 공개하지 말고, 필요하면 Vercel 의 **Deployment Protection**(비밀번호/SSO)을 한 겹 더 거세요.

환경 변수를 바꾼 뒤에는 Vercel에서 **Redeploy** 해야 반영됩니다.

## 6. 모바일 앱 빌드

`SUPABASE_URL` / `SUPABASE_ANON_KEY` 는 `mobile/app.config.js` 가 **빌드 시점에** 읽어 앱에 넣습니다.

```powershell
cd mobile
npx expo prebuild -p android     # 아이콘·스플래시·권한(app.json)이 함께 반영됩니다
npx expo run:android
```

> EAS Build 를 쓴다면 같은 이름으로 EAS **환경 변수/Secrets** 에 등록하세요.

> 참고: 이전에는 `app.config.js` 가 `app.json` 을 덮어써서 아이콘·스플래시·플러그인·권한이 네이티브 빌드에 적용되지 않았습니다.
> 이제 `app.json` 을 기반으로 병합됩니다. 이미 만들어 둔 `mobile/android` 폴더가 있다면 `prebuild --clean` 으로 다시 생성하세요.

## 9. 알아둘 점

- **무료 플랜**: Supabase 무료 프로젝트는 약 1주일간 접속이 없으면 일시 중지됩니다. 대시보드에서 **Restore** 하면 되고, 여행 직전에는 한 번 접속해 두세요.
- **오프라인**: 앱은 마지막으로 받은 데이터를 기기에 저장해 두므로, 해외에서 데이터가 안 터져도 일정·티켓·회화는 볼 수 있습니다. 메모는 오프라인에서 쓰고 연결되면 자동으로 올라갑니다.
- **로그아웃**: 앱 도구 → 설정 → 로그아웃. 이 기기에 저장된 여행 복사본이 지워집니다.
- **백업**: Supabase 대시보드 **Database → Backups** 를 확인하세요. 중요한 예약 정보는 따로 사진/PDF로도 보관하길 권합니다.
