# 04. 운영 매뉴얼

> 대상: 서비스를 설치·배포·운영하는 사람(운영자/관리자)
> 자세한 최초 설정 화면 캡처 수준의 안내는 [배포 가이드](배포-가이드.md)에 있고, 이 문서는 **운영 절차·점검·장애 대응** 중심입니다.
> 짝 문서: [01 아키텍처](01-시스템-아키텍처.md) · [02 DB 설계](02-데이터베이스-설계.md) · [03 소스 설명](03-소스-설명.md) · [05 사용자 매뉴얼](05-사용자-매뉴얼.md)

## 1. 운영 구성 요약

| 대상 | 접속/배포 | 담당 |
|------|-----------|------|
| Supabase 프로젝트 | 대시보드(SQL Editor, Auth, Backups) | DB·로그인·함수 |
| 사용자 웹 | Vercel 프로젝트 A (`web/`) | 여행자용 |
| 운영 콘솔 | Vercel 프로젝트 B (`admin/`) — **사용자 웹과 다른 주소** | 관리자만 |
| 모바일 앱 | EAS Build → APK(`preview`) / AAB(`production`) | 여행자용 |
| Google Cloud | Maps SDK for Android · Maps JavaScript · Places API (New) · (Geocoding) | 지도·장소 검색 |

## 2. 최초 설치 체크리스트

1. **Supabase 프로젝트 생성** → Project Settings → API 에서 `Project URL` 과 `anon public` 키 확인(**`service_role` 은 복사/사용 금지**).
2. **SQL 적용(SQL Editor, 번호 순서)**: `0001` → `0002` → `0003` → `0004` → `0005` → `0006` → `0007`.
3. **로그인 설정**: Authentication → Providers → Email 켜기. 가입 허용 여부, 이메일 인증 정책 결정. (운영 콘솔의 "계정 추가"는 가입 허용이 켜져 있어야 동작)
4. **본인 계정 가입 후 첫 관리자 지정**:
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'me@example.com'
   on conflict do nothing;
   ```
5. **환경 변수 준비**(커밋 금지)
   - 루트 `.env`: `google_maps_api_key`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`
   - `web/.env`: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_GOOGLE_MAPS_API_KEY`
   - `admin/.env`: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
6. **Google Cloud**: 사용할 API 활성화(아래 §6) + **결제 계정 연결** + API 키 제한 설정.
7. **배포**: Vercel 프로젝트 2개(web, admin), EAS 환경변수 등록 후 APK 빌드.

## 3. 로컬 개발·검증

PowerShell 에서는 `&&` 체인이 깨질 수 있으므로 **폴더를 이동한 뒤 한 줄씩** 실행합니다.

| 대상 | 폴더 | 명령 | 주소 |
|------|------|------|------|
| 사용자 웹 | `web/` | `npm install` → `npm run dev` | http://localhost:5173 |
| 운영 콘솔 | `admin/` | `npm install` → `npm run dev` | http://localhost:5174 |
| 모바일(웹 미리보기) | `mobile/` | `npm install` → `npx expo start --web --port 8081` | http://localhost:8081 |
| 모바일 번들 검증 | `mobile/` | `npx expo export --platform android --output-dir ../.tmp-export` (검증 후 `.tmp-export` 삭제) | — |
| 빌드 확인 | `web/`, `admin/` | `npx vite build` | — |

> 네이티브 지도·카메라는 **Expo Go 불가**. 실제 단말 확인은 APK 설치(또는 `npx expo prebuild -p android` 후 `npx expo run:android`)로 합니다.

## 4. 배포 절차

### 4-1. 웹(Vercel)
1. 저장소를 Vercel 에 연결해 **프로젝트 2개**를 만듭니다. 루트 디렉터리를 각각 `web`, `admin` 으로 지정.
2. 각 프로젝트의 Environment Variables 에 위 `VITE_*` 값을 등록하고 재배포.
3. 배포 후 로그인·여행 조회·장소 검색이 되는지 확인(체크리스트 §8).

### 4-2. 모바일 앱(EAS)
1. EAS 환경변수에 `google_maps_api_key`, `SUPABASE_URL`, `SUPABASE_ANON_KEY` 를 등록(대시보드 또는 `eas env:create`).
2. APK(내부 배포) 빌드:
   ```powershell
   cd mobile
   npx eas-cli build -p android --profile preview
   ```
3. 빌드 완료 링크로 휴대폰에 APK 설치. **버전은 빌드마다 자동 증가**하며 앱 설정 화면 맨 아래에 `v버전 (빌드)` 로 표시됩니다.
4. 스토어 배포용은 `--profile production`(AAB).

> **이전 크래시 이력**: 설치 직후 즉시 종료되던 문제는 R8(코드 축소)이 WorkManager/Room 클래스를 제거해서 생겼고, `app.json` 의 `expo-build-properties` keep 규칙으로 해결했습니다. **이 규칙을 지우지 마세요.**

### 4-3. DB 변경 배포
- 새 기능이 DB 변경을 포함하면 `supabase/migrations/` 에 **새 번호 SQL 파일**을 추가하고, 앱·웹 배포 **전에** SQL Editor 에서 먼저 적용합니다.
- 예: `0007_shared_plans.sql` 을 적용하지 않으면 앱의 공유 링크가 실패합니다.

## 5. 운영 콘솔 사용(관리자)

로그인: 운영 콘솔 주소 → 관리자로 등록된 계정만 가능(일반 계정은 거부).

| 메뉴 | 용도 | 주요 작업 |
|------|------|-----------|
| 운영 대시보드 | 현황 파악 | 전체·신규 가입자, 오늘/7일/30일 접속자, 정지·미인증 수, 일별 그래프(한국 시간) |
| 사용자 관리 | 계정 관리 | 검색(이메일·이름·**IP**), 상태 필터, **계정 추가**, 행 클릭 → 상세 패널 |
| 접속 로그 | 접속 기록 | 가입·로그인·앱 실행·로그아웃, 기기·이벤트·이메일 필터, **CSV 내보내기** |
| 인사이트 | 사용 분석 | 단계별 전환율, 시간대·요일·기기, 인기 국가·목적지 Top10, 콘텐츠 총량, 휴면 수 |
| 운영 기록 | 감사 | 운영자의 정지·해제·수정·삭제·권한·관광지 변경 자동 기록(수정·삭제 불가) |
| 관광지 관리 | 추천 관광지 | 나라별 등록·수정·공개/숨김·삭제, **CSV 일괄 등록**·내보내기 |

### 5-1. 자주 하는 운영 작업

| 상황 | 처리 방법 |
|------|-----------|
| **비밀번호를 잊었다고 연락** | 사용자 상세 → 비밀번호 관리 → **임시 비밀번호로 초기화**(로그인 중 기기 모두 로그아웃, 다음 로그인 때 변경 요구) 또는 **재설정 메일** 발송. 임시 비밀번호는 **한 번만 표시**되니 안전한 방법으로 전달 |
| 새 사용자 계정을 대신 만들기 | 사용자 관리 → 계정 추가(임시 비밀번호 자동 생성, 인증 완료·변경 요구·관리자 권한 옵션) |
| 문제 계정 차단 | 상세 → **정지**(기간·사유 지정). 로그인 중인 기기도 곧 로그아웃. 사유는 운영자만 보임 |
| 관리자 추가/해제 | 상세 → 관리자 지정/해제. **자기 자신은 정지·삭제·권한 해제 불가**, 관리자 계정은 권한을 먼저 해제해야 정지·삭제 가능 |
| 계정 삭제 | 상세 → 계정 삭제(**그 사용자의 여행·메모 등이 연쇄 삭제**, 되돌릴 수 없음) |
| 추천 관광지 대량 등록 | 관광지 관리 → **양식 받기** → 채우기 → CSV 선택. 오류 줄은 이유와 함께 표시, 중복(나라·도시·이름 동일)은 건너뜀 |
| 관광지를 잠시 내리기 | 해당 항목의 "공개"를 끔(삭제하지 않음). 이미 사용자가 가져간 장소는 그대로 남음 |

> 관리자도 **다른 사용자의 여행·메모 내용은 볼 수 없습니다.** 문의 대응 시 내용 확인이 필요하면 사용자에게 화면 공유를 요청하세요.

### 5-2. 관광지(CSV) 양식
헤더: `country,city,name,name_local,category,lat,lng,address,memo`
- `country`: 국가 코드 2자리(예 `JP`) 또는 한글 이름 · `category`: 관광/맛집/숙소/교통
- 좌표는 구글 지도에서 장소를 우클릭하면 나오는 `35.7148, 139.7967` 형식 값을 사용(콘솔의 "구글 지도에서 확인" 링크로 검증).

## 6. Google Cloud / 지도 API 점검

| 항목 | 확인 |
|------|------|
| 활성화 API | **Maps SDK for Android**, **Maps JavaScript API**, **Places API (New)** (필요 시 Geocoding API) |
| 결제 | 결제 계정 연결 필수(Places·Geocoding). 미설정이면 `REQUEST_DENIED` |
| 키 제한 | 허용 API 목록에 위 API 포함 · Android 앱 제한(패키지 `com.honeymoon.guide` + 서명 SHA-1) · 웹 키는 HTTP 리퍼러 제한 |
| 비용 | Places 는 호출당 요금. 앱/웹의 "웹에서 찾기"는 **사용자가 누를 때만** 호출. 일일 한도·예산 알림을 설정 |
| 증상별 | `REQUEST_DENIED`/403 → API 미활성·결제 미연결·키 제한 문제 / 지도가 회색 → 키 누락 또는 SHA-1 불일치 |

## 7. 데이터 관리

### 7-1. 정기 정리 SQL (SQL Editor)
```sql
-- 접속 로그(IP 포함)는 개인정보 — 90일 지난 것 삭제
delete from public.access_logs where created_at < now() - interval '90 days';

-- 만료된 공유 링크 삭제
delete from public.shared_plans where expires_at < now();
```
> 보관 기간은 개인정보 처리방침에 맞춰 정하고, 가입자에게 IP 수집 사실을 안내하세요.

### 7-2. 백업·복구
- Supabase 대시보드의 **Backups**(플랜에 따라 자동 일일 백업) 확인. 중요한 변경(대량 삭제·스키마 변경) 전에는 수동으로 `pg_dump` 를 받아 두세요.
- 복구는 새 프로젝트에 덤프를 복원 후 앱·웹의 URL/anon 키를 교체하는 방식이 가장 안전합니다.
- 사진 **원본은 서버에 없습니다**(기기에만). 사용자가 휴대폰을 바꾸면 사진 원본은 옮겨지지 않고 메타데이터만 남습니다.

### 7-3. 예전 데이터 이전(선택)
`backend/`(Spring Boot, H2) 데이터를 옮길 때만 사용합니다([배포 가이드](배포-가이드.md) §7). 신규 운영과 무관합니다.

## 8. 릴리스 점검 체크리스트

- [ ] `web`, `admin`: `npx vite build` 오류 없음
- [ ] `mobile`: `npx expo export --platform android` 통과
- [ ] 새 SQL 이 있다면 **먼저** Supabase 에 적용했는가
- [ ] 사용자 웹(5173) CRUD: 여행·장소·바우처·회화·준비물 / 운영 콘솔(5174) 관리자만 로그인
- [ ] 모바일 웹 미리보기(8081): 홈·여행·지도(마커·일정 패널·내 위치)·기록·도구
- [ ] 장소 검색(지도/추천 관광지 "웹에서 찾기") 동작, 비용 한도 확인
- [ ] 새 APK 를 단말에 설치해 **실기기**에서 시작·로그인·지도·위치 권한 확인
- [ ] 커밋에 `.env`·키·`service_role` 이 없는가

## 9. 장애 대응 가이드

| 증상 | 원인 후보 | 조치 |
|------|-----------|------|
| 앱 설치 직후 **바로 종료** | R8 이 WorkManager/Room 제거 | `app.json` 의 `extraProguardRules` 유지 후 재빌드 |
| 앱 로딩이 끝나지 않음 | 네트워크/서버 지연 | 시작 시 캐시 먼저 표시 후 새로 받음. 오프라인이면 캐시로 계속 사용됨. 설정 → 서버에서 불러오기 |
| 로그인 화면에서 "관리자 권한이 없는 계정" | `admins` 미등록 또는 SQL 미적용 | 관리자 지정 SQL 실행, `0002~0005` 적용 확인 |
| **공유 링크 만들기/열기 실패** | `0007_shared_plans.sql` 미적용, 링크 만료(14일), 로그아웃 상태 | SQL 적용 확인, 새 링크 생성, 로그인 후 링크 열기 |
| 주변 탐색/장소 검색 **오류 안내** | Places API (New) 미활성·결제·키 제한 | §6 점검. 앱은 새 API → 예전 API 순으로 시도하며 이유를 문구로 보여 줌 |
| 지도가 회색/마커 없음 | 키 누락, SHA-1 제한 불일치, 일정에 좌표 없는 장소 | 키·제한 확인. 위치 없는 장소는 목록에만 "위치 없음"으로 표시 |
| 환율이 "갱신 전" | 환율 API 일시 오류 | 앱이 대체 주소를 시도. 계속 실패면 환율을 **직접 입력** |
| 추천 관광지 "준비 중" | 해당 나라 카탈로그 미등록 | 운영 콘솔에서 등록하거나, 사용자는 "웹에서 찾기"로 직접 등록 |
| 사용자가 임시 비밀번호로 들어가면 다른 화면 못 감 | 정상 동작(강제 변경) | 새 비밀번호 설정 안내 |
| 웹 콘솔에서 저장했는데 앱에 안 보임 | 앱 캐시 | 앱 설정 → 서버에서 불러오기(또는 앱 재시작) |
| 일차(일정)가 사라짐 | 여행 기간을 줄임 | 기간 밖 날짜의 일차·일정은 **자동 삭제**됨(트리거). 기간 수정 전 안내 |

## 10. 보안 점검표 (분기별)

- [ ] 저장소와 배포 환경 어디에도 `service_role` 키가 없다
- [ ] `.env`, 키스토어, `credentials` 가 Git 에 없다(`git log -p` 로 검색)
- [ ] 모든 사용자 테이블에 RLS 가 켜져 있다(대시보드 → Authentication → Policies)
- [ ] `anon` 역할에 테이블·함수 권한이 없다
- [ ] 관리자 목록(`select * from public.admins`)이 현재 담당자와 일치
- [ ] Google API 키 제한(앱 서명·리퍼러)과 일일 한도가 적절
- [ ] 접속 로그(IP) 보관 기간을 지켰다
- [ ] 퇴사/교체된 관리자는 **권한 해제 후** 정지·삭제

## 11. 키 교체(유출 의심 시)

1. Google API 키: Google Cloud 에서 **새 키 발급 → 제한 설정 → 환경변수 교체(.env, Vercel, EAS) → 앱 재빌드·웹 재배포 → 옛 키 삭제**.
2. Supabase anon 키: 공개 가능한 키이므로 유출 자체는 RLS 가 막지만, 필요하면 대시보드에서 키를 재생성하고 같은 순서로 교체.
3. `service_role` 키가 한 번이라도 노출됐다면 **즉시 재생성**하고 노출 경로를 정리.
