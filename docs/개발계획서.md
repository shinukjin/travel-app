- **프로젝트명:** Private Honeymoon Guide (스페인·포르투갈)
- **문서 버전:** v2.1
- **작성일:** 2026-11-09
- **기반 명세:** v2.0 (핵심 기능 + 바이브 코딩 단계)
- **상태:** 구현 진행 (backend / admin / mobile 스켈레톤 완료)

## 1. 프로젝트 개요

### 1.1 목적

현지에서 필요한 핵심 정보(항공/교통, 일정, 맛집, 회화) 조회와 함께, 순간의 감상을 기록하는 메모 기능, 위치/시간 기반 사진 자동 분류, 여행 종료 시 **온디바이스 하이라이트 영상** 생성을 제공하는 올인원 개인용 앱.

### 1.2 개발 방식

AI 에이전트(Cursor 등)를 활용한 바이브 코딩. 아래 확정 결정과 단계별 범위를 기준으로 구현한다.

### 1.3 확정 결정 (2026-11-09)

| 항목 | 결정 | 이유 |
|------|------|------|
| 미디어 원본 | **기기 로컬만 보관** | 온디바이스 하이라이트, 오프라인 여행, 개인 앱 |
| 서버 동기화 | 시간 / GPS / Trip ID 등 **메타데이터만** | 원본 업로드 없음 |
| 인증 | **없음** (API 개방) | 개인용, 가장 빠른 스타트 |
| DB | **H2 파일 모드** | 개발 속도. 이후 MySQL 프로파일 추가 가능 |

## 2. 시스템 아키텍처 및 기술 스택

### 2.1 구성

```
travel/
  backend/    Spring Boot 3.3 + JDK 17 + Spring Data JPA + H2
  admin/      Vue 3 + Vite + Vue Router
  mobile/     React Native (Expo, Android Dev Client)
  docs/       본 개발계획서
```

```
Admin (Vue 3)  --REST CRUD-->  Spring Boot API  -->  H2 (파일 DB)
Mobile (Expo)  --오프라인 캐시 후 동기화-->  Spring Boot API
Mobile         -->  AsyncStorage + 기기 사진/영상
Mobile         -->  ffmpeg-kit (온디바이스 인코딩)
```

### 2.2 Mobile App (Android)

- **프레임워크:** React Native (Expo)
- **필수 이유:** `react-native-maps`, `ffmpeg-kit-react-native`는 Expo Go에서 동작하지 않음. `npx expo prebuild` + Dev Client로 빌드.
- **주요 라이브러리**
  - `React Navigation` (bottom tabs)
  - `react-native-maps`
  - `expo-location`
  - `expo-speech`
  - `expo-camera` / `expo-media-library`
  - `ffmpeg-kit-react-native` (하이라이트 인코딩)
  - `expo-av` (결과 영상 재생)
  - `@react-native-async-storage/async-storage` (오프라인 캐시)

### 2.3 Admin Web (PC)

- Vue 3 + Vite
- 개발 포트 5173, `/api` → `localhost:8080` 프록시
- 여행 기간 설정, 데일리 일정 빌더, 장소/바우처/회화 사전 등록

### 2.4 Backend API

- Spring Boot (JDK 17) + Spring Data JPA
- H2 파일 모드 (`./data/honeymoon`), `ddl-auto: update`
- CORS `*` (개인 로컬용)
- 패키지: `com.honeymoon.guide` (`domain` / `repository` / `service` / `web`)

## 3. 핵심 기능 명세

### 3.1 Mobile App

#### A-1. 기간별 일정 관리 및 타임라인 (Offline-First)

- 스페인 / 포르투갈 등 Trip 단위 탭 분리
- N일차 상세 타임라인
- 첫 실행 시 API에서 trips / schedules / places / vouchers / phrases를 받아 AsyncStorage 캐시
- 이후 네트워크 없이도 캐시로 조회

#### A-2. 지도 및 주변 길찾기 (GPS)

- `expo-location` + `react-native-maps`
- 선택한 일차(또는 오늘) 일정 마커 + 현재 위치
- 마커 탭 시 Google Maps 길찾기 딥링크 (`google.navigation:q=lat,lng`)
- Google Maps API 키가 없으면 OSM 타일 폴백 가능하도록 설계

#### A-3. 오프라인 바우처 뷰어 및 상황별 현지 회화 (TTS)

- 네트워크 없이 예약 내역(항공/호텔/티켓) 텍스트 뷰어
- `expo-speech`로 원어민 발음 재생 (`es-ES` / `pt-PT`)

#### A-4. 순간 기록 메모장 (글 + 사진)

- 감상, 지출, 팁 등을 즉시 기록하는 퀵 메모 탭
- 제출 시 현재 GPS를 붙여 AsyncStorage 큐에 `pending` 저장
- 온라인 전환 시 `POST /api/memos` 동기화
- `clientId`로 중복 POST 방지
- 사진 파일은 업로드하지 않고 로컬 URI만 메타에 포함

#### A-5. 기간별 사진 자동 분류 및 온디바이스 하이라이트

- 앱 내 촬영 또는 갤러리 불러오기
- EXIF(시간, GPS) 또는 현재 위치 fallback으로 해당 Trip에 매핑
- 매칭 실패 시 Trip 선택 다이얼로그
- 날짜별 그룹 그리드
- 여행 종료 시 `ffmpeg-kit-react-native`로 기기 내부에서 사진 2초 슬라이드쇼 concat → mp4
- 1차 범위: 트랜지션·BGM은 생략 가능. 안정적인 concat 우선
- 완료 후 `expo-av` Video로 재생, 원하면 MediaLibrary에 저장

### 3.2 Admin Web

#### B-1. 여행 기간(Trip) 생성 및 관리

- 제목, 국가(`ES`/`PT`), 시작일/종료일
- 저장 시 1일차부터 N일차 Schedule 자동 생성
- 날짜 변경 시 일차 재생성

#### B-2. 드래그 앤 드롭 일정 빌더

- 좌측: 사전 정의 장소/맛집 카드
- 우측: 선택한 Day 타임라인
- `vuedraggable`으로 배치·순서 변경
- 저장 시 `PUT /schedules/{id}/items`

#### B-3. 장소 / 바우처 / 회화 CRUD

- 장소: 이름, 분류(맛집/관광/숙소/교통), lat/lng, 주소, 메모
- 바우처: 항공/호텔/티켓 텍스트
- 회화: 상황, 한국어, 현지어, locale

## 4. 데이터 모델

```
Trip 1 ── N Schedule (일차)
Schedule 1 ── N ScheduleItem (타임라인)
Place 1 ── N ScheduleItem
Trip 1 ── N Voucher
Trip 1 ── N Phrase
Trip 1 ── N Memo
Trip 1 ── N MediaLog
```

### 4.1 엔티티 필드

| 엔티티 | 주요 필드 |
|--------|-----------|
| **Trip** | `title`, `country` (`ES`/`PT`), `startDate`, `endDate` |
| **Schedule** | `trip`, `dayIndex`, `date`, `title` |
| **Place** | `name`, `category`, `lat`, `lng`, `address`, `memo` |
| **ScheduleItem** | `schedule`, `place`, `sortOrder`, `startTime`, `note` |
| **Voucher** | `trip`, `title`, `type`(항공/호텔/티켓), `body` |
| **Phrase** | `trip`, `situation`, `ko`, `localText`, `locale` (`es-ES`/`pt-PT`) |
| **Memo** | `trip`, `content`, `photoUri`(기기 경로), `lat`, `lng`, `createdAt`, `clientId` |
| **MediaLog** | `trip`, `localUri`, `mediaType`, `capturedAt`, `lat`, `lng` |

서버는 파일 바이너리를 저장하지 않는다. `photoUri` / `localUri`는 기기 경로 문자열이다.

## 5. REST API

기본 prefix: `/api`

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET/POST/PUT/DELETE | `/trips` | 여행 기간. POST/날짜변경 시 Day 자동 생성 |
| GET | `/trips/{id}/schedules` | 일차 + items + place |
| PUT | `/schedules/{id}/items` | 타임라인 일괄 저장 (Admin DnD) |
| GET/POST/PUT/DELETE | `/places` | 장소 카탈로그 |
| GET/POST/PUT/DELETE | `/vouchers` | 바우처 |
| GET/POST/PUT/DELETE | `/phrases` | 회화 |
| GET/POST | `/memos?tripId=` | 메모 메타 |
| GET/POST | `/media-logs?tripId=` | 미디어 메타 |

시드: 스페인(10.1~10.7), 포르투갈(10.8~10.12) 샘플 Trip + 장소 일부 (`data.sql`).

## 6. 단계별 구현 계획 (바이브 코딩)

원명세 Step 1~5에 Step 0(스캐폴드)을 앞에 둔다.

### Step 0. 모노레포 스캐폴드

- backend / admin / mobile 프로젝트 생성
- 루트 `README.md`에 실행 순서 (백엔드 → 어드민 → Expo prebuild)
- Android 권한: CAMERA, READ/WRITE_MEDIA, ACCESS_FINE_LOCATION

### Step 1. Spring Boot 스키마 고도화

원 프롬프트 요지:

> Place, Voucher에 더해 Trip, Schedule, Memo, MediaLog를 설계하고 연관관계와 CRUD REST API를 작성한다.

본 계획에서의 확장:

- ScheduleItem, Phrase를 함께 두어 일정 빌더·TTS가 동작하게 한다.
- Trip 저장 시 일차 자동 생성.
- H2 시드 데이터.

### Step 2. Vue.js Admin — 기간 설정 및 일정 빌더

원 프롬프트 요지:

> 달력으로 시작일/종료일을 지정하면 1~N일차 탭이 자동 생성되고, Day 탭 안에서 장소 카드를 드래그 앤 드롭한다.

본 계획에서의 확장:

- 장소 / 바우처 / 회화 CRUD 페이지.
- 인증 없음. UI는 Vue 기본 + 가벼운 CSS.

### Step 3. Expo — 라우팅 및 퀵 메모

원 프롬프트 요지:

> 바텀 탭을 [일정], [지도], [메모], [추억] 4개로 재구성. 메모는 텍스트+사진+GPS를 AsyncStorage에 저장하고, 네트워크 연결 시 Spring Boot로 동기화.

본 계획에서의 확장:

- 일정 탭: Trip 세그먼트, N일차 타임라인, 바우처, TTS 회화
- 지도 탭: 일정 마커 + 길찾기 딥링크
- 메모 사진은 파일 업로드 없이 로컬 URI만 동기화

### Step 4. Expo — 사진 촬영 및 메타데이터 자동 분류

원 프롬프트 요지:

> expo-camera / expo-media-library로 촬영·불러오기. 시간·GPS로 진행 중인 Trip과 매칭하고 날짜별 그리드로 표시.

본 계획에서의 확장:

- 로컬 인덱스(AsyncStorage) + `POST /api/media-logs` 메타만 전송

### Step 5. 온디바이스 하이라이트 영상

원 프롬프트 요지:

> 추억 탭 상단 버튼 → Trip 사진을 시간순으로 불러 → ffmpeg-kit로 각 사진 2초 mp4 인코딩 → expo-av로 재생.

본 계획에서의 제약:

- `ffmpeg-kit-react-native`는 아카이브 라이브러리. Android min-gpl을 핀하고 Expo config plugin으로 Dev Client에 포함.
- 1차: 2초 슬라이드쇼 concat. 트랜지션·BGM은 후순위.
- 해상도 720p, 최대 약 30장. 사진 0장이면 버튼 비활성.
- 결과 파일: 앱 문서 폴더 `highlight-{tripId}.mp4`

## 8. 기술적 제약 및 주의사항

1. **파일 업로드 API를 만들지 않는다.** 원본은 기기에만 둔다.
2. **하이라이트는 CPU/배터리 부하가 크다.** 1차는 720p, 장수 제한.
3. **지도 키.** Google Maps API 키는 `app.json` extra. 없으면 OSM 폴백.
4. **H2는 개발용.** 운영 DB가 필요하면 `application.yml`에 MySQL/PostgreSQL 프로파일만 추가.
5. **Expo Go 사용 불가.** maps / ffmpeg 네이티브 모듈 때문에 Dev Client 필수.
6. **인증 없음.** 같은 네트워크에서 API가 열려 있다. 공인망 배포 시 별도 보안 계획이 필요하다.
